# 住友商事 PPTX 作成スキル

任意のテキスト/Markdown/構成案を、**住友商事ブランドの標準テンプレート**に流し込んで新規PPTXを生成する。
ゼロから図形を描くのではなく、同梱の `assets/template.pptx` を土台に `assets/build.py` で組み立てる。

## 最重要ルール

**利用者が細かい指示を書かなくても、以下は常に適用する。**
「住商パワポで作って」のような一言で呼ばれた場合も、この章の6項目はすべて既定で守ること
（利用者からの明示的な上書き指示があった場合のみ、そちらを優先する）。

- **1スライド1メッセージ。タイトルは体言止めにせず、言い切りの文にする。**
  「導入効果について」ではなく「導入で作業は3日から10分になる」のように、そのページの主張を文で書く。
  1枚に主張が2つ以上あるなら、スライドを分ける。
- **図は必ず `figure`（PowerPointネイティブ図形）で作る。画像で貼らない。** ← ユーザー必須ルール
  納品後に**文言の修正・図形サイズの変更・色替えがPowerPoint上でできる**状態で渡すため。
  SVG/PNGを図解として貼るのは禁止（build.py がSVG貼り付けをエラーにする）。
  `image` は**写真・スクリーンショットなど、図形で再現できないものだけ**に使う。
- **フォントは必ず16pt以上。** 本来11pt/13ptの小見出し・リードも16pt以上に引き上げる（build.py が自動で下限を強制）。`figure` 内の文字も同じく16pt以上。
- **図解を中心に。文字だけのスライドにしない。** 本文スライドは原則として内容を表す図（プロセス図・比較・マトリクス・構成図など）を `figure` で作る。箇条書きだけで済ませない（→「図解（figure）」参照）。
- ブランド色・ロゴ・ページ番号・背景はテンプレ（マスタ/レイアウト/テーマ）が自動付与する。**勝手に色やロゴを足さない。**

## テンプレートの構成（assets/template.pptx）
4種類のスライドを土台に持つ（このスキルの対応範囲）:

| 種別 | spec の type | レイアウト | プレースホルダ（idx） | 用途 |
|---|---|---|---|---|
| 表紙 | （固定） | 表紙 1 | title=0 / subtitle=1 / body=13(会社名・日付) | 先頭1枚 |
| 目次 | （固定） | 目次 | "Contents" + 項目テキストボックス（点線リーダー付き） | 章扉(無ければ本文)から自動生成 |
| 本文グリッド | `content`（既定） | 本文ページ1（グリッド） | section=10(ティール小見出し) / title=0(26pt太字) / lead=11(リード) / content=12(本文 or 図) | 本文（`figure`で図配置） |
| 章扉 | `section` | 中扉（グラフィック/写真1〜6） | title=0(36pt太字) / number=11(大きな番号・自動採番) | 章の区切り（`variant`で選択） |
| サマリー | `summary` | サマリーページ | section=10 / title=0 / lead=11 / content=14(本文 or 図) | 要点まとめ（右上リボン背景・`figure`可） |
| エンド | （固定） | エンドページ 1 | title=0("Thank You.") / subtitle=1(謝辞) | 末尾1枚 |

- **章扉の `variant`**: `graphic`（既定・グラフィック背景）/ `photo1`〜`photo6`（写真背景。タイトルは白で表示）。
- **本文・サマリーの `figure`**: ネイティブ図形での図解。`body` なし→図を全幅配置／`body` あり→**左=本文・右=図の2カラム**（`image` も同じ扱いだが写真専用）。

### ブランド仕様（参考）
- サイズ: 16:9 (12192000×6858000 EMU)、ページ番号は0始まり（表紙=0）。
- 主役色: ティール `#15B5AA`（テーマの `schemeClr val="tx2"`）。アクセント=88DBDF/7392F5/8557A7/96DC00/FF5A41/FFB41E。
- フォント: 日本語=メイリオ、英数字もメイリオで統一。
- 本文ページの型: ①ティール小見出し → ②26pt太字タイトル → ③リード文 → ④本文（●箇条書き可）。

## ワークフロー

### Step 1: 入力を spec.json に構造化
ユーザーの内容（テキスト/Markdown/会話）を読み取り、次のJSONに整理する。

```json
{
  "title": "プレゼンタイトル",
  "subtitle": "サブタイトル／部署名",
  "date": "住友商事株式会社 ｜ 2026年6月23日",
  "thanks": "ご清聴ありがとうございました。",
  "slides": [
    {
      "type": "section",
      "title": "章タイトル（章扉。number省略で 01,02… を自動採番）"
    },
    {
      "type": "content",
      "section": "セクション名（上部ティール小見出し・任意）",
      "title": "ページタイトル（必須）",
      "lead": "リード文（1〜2行・任意）",
      "body": [
        "ただの段落",
        {"text": "箇条書き項目", "bullet": true},
        {"text": "字下げ", "bullet": true, "level": 1},
        {"text": "強調見出し", "bold": true}
      ]
    },
    {
      "type": "content",
      "section": "サービス概要",
      "title": "データ活用の全体像",
      "lead": "抽出から意思決定までを一気通貫で支援。",
      "figure": {
        "viewBox": [1180, 500],
        "shapes": [
          {"kind": "roundRect", "x": 40, "y": 180, "w": 300, "h": 140, "radius": 14,
           "fill": "teal", "text": "抽出", "size": 18, "bold": true},
          {"kind": "arrow", "points": [[352, 250], [416, 250]]},
          {"kind": "roundRect", "x": 428, "y": 180, "w": 300, "h": 140, "radius": 14,
           "fill": "white", "line": "teal", "text": "分析", "size": 18},
          {"kind": "arrow", "points": [[740, 250], [804, 250]]},
          {"kind": "roundRect", "x": 816, "y": 180, "w": 300, "h": 140, "radius": 14,
           "fill": "pale", "line": "none", "text": "意思決定", "size": 18}
        ]
      }
    },
    {
      "type": "content",
      "title": "導入効果",
      "lead": "手作業を自動化。",
      "body": [ {"text": "工数削減", "bullet": true} ],
      "figure": {
        "viewBox": [560, 520],
        "shapes": [
          {"kind": "roundRect", "x": 30, "y": 40, "w": 500, "h": 180, "radius": 12,
           "fill": "gray", "line": "none",
           "lines": [{"text": "導入前", "size": 18, "bold": true}, {"text": "手作業で3日", "size": 16}]},
          {"kind": "arrow", "points": [[280, 240], [280, 290]]},
          {"kind": "roundRect", "x": 30, "y": 310, "w": 500, "h": 180, "radius": 12,
           "fill": "teal",
           "lines": [{"text": "導入後", "size": 18, "bold": true}, {"text": "自動で10分", "size": 16}]}
        ]
      }
    },
    {
      "type": "section",
      "variant": "photo1",
      "title": "今後の展望"
    },
    {
      "type": "summary",
      "section": "まとめ",
      "title": "要点タイトル",
      "lead": "任意",
      "figure": { "viewBox": [1180, 440], "shapes": [] }
    }
  ]
}
```

各 `slides[]` 要素の `type`（省略時 `content`）:
- `content`: 本文グリッド。`section`/`title`/`lead` ＋ `body`（テキスト）か `figure`（図）か両方。
- `section`: 章扉。`title` のみ使用。`variant`（`graphic`/`photo1`〜`photo6`）で背景選択。`number` 省略で 01,02… を自動採番。
- `summary`: サマリー。`content` と同じフィールド（`figure` 可）。

### 図解（figure）— 必ずネイティブ図形で作る
**本文スライドは図解を基本にする。** 図は `figure` に書く。build.py がオートシェイプ＋テキストフレームとして生成するので、
納品後にユーザーが**文言を直せる／図形を動かせる／サイズを変えられる／色を変えられる**。画像で貼ってはいけない。

```json
"figure": {
  "viewBox": [1180, 500],
  "shapes": [
    {"kind": "roundRect", "x": 40, "y": 60, "w": 300, "h": 120, "radius": 12,
     "fill": "teal", "text": "入力", "size": 18, "bold": true},
    {"kind": "arrow", "points": [[352, 120], [416, 120]], "color": "teal"},
    {"kind": "roundRect", "x": 428, "y": 60, "w": 300, "h": 120,
     "fill": "white", "line": "teal",
     "lines": [{"text": "処理", "size": 18, "bold": true}, {"text": "補足", "size": 16, "color": "ink"}]},
    {"kind": "text", "x": 40, "y": 220, "w": 700, "h": 44, "text": "注釈", "size": 16, "align": "l"},
    {"kind": "line", "points": [[190, 300], [190, 360], [900, 360]], "arrow": true, "dash": true}
  ]
}
```

**座標系**: `viewBox` は `[w, h]`（または `[x, y, w, h]`）。配置枠にアスペクト比を保って内接する。
**全幅配置は約 2.35:1**（例 `[1180, 500]`）、**2カラム右側は約 1.1:1**（例 `[560, 520]`）。
`x/y/w/h` と `points` はこの座標系。**`size` だけは実寸pt**（図座標ではない。16pt未満は自動で16ptに上がる）。

**`kind`**:

| kind | 図形 | 主な用途 |
|---|---|---|
| `roundRect` | 角丸長方形（`radius` で丸み） | 既定。プロセスの箱・カード |
| `rect` | 長方形 | 帯・背景ブロック |
| `ellipse` | 楕円 | 円形ノード |
| `chevron` / `pentagon` | 山形 | ステップの流れ |
| `diamond` | ひし形 | 分岐・判断 |
| `arrowBox` | ブロック矢印 | 大きな流れ |
| `text` | テキストボックス（塗り/線なし） | 見出し・注釈。既定は左寄せ・上寄せ |
| `arrow` / `line` | 直線・折れ線 | `points` で頂点指定。`arrow: true` で矢じり、`dash: true` で点線 |

**図形の属性**: `fill` / `line`（枠線色）/ `lineWidth`(pt) / `text` または `lines`（複数行）/ `size`(pt) / `bold` /
`color`（文字色）/ `align`(`l`/`c`/`r`) / `valign`(`t`/`m`/`b`)。線は `color` / `width`(pt) / `arrow` / `dash`。

**色名**（ブランド準拠。`#RRGGBB` も可、`"none"` で塗り/線なし）:
`teal`(#15B5AA・主役) / `tealDark` / `pale`(#EFF5F5・淡背景) / `white` / `black` / `ink`(補足文字のグレー) /
`gray` / `grayLine` / `dark` / アクセントは `blue` `cyan` `purple` `green` `red` `yellow`。
**濃い塗り（teal/dark 等）の上の文字は自動で白**になる。

**作図の指針**:
- 角丸長方形＋矢印のプロセス図、左右比較、2×2マトリクス、構成図を積極的に使う。
- 文字が16pt以上なので、**箱は大きく・要素は少なく**。1つの図に詰め込みすぎない（箱は目安8個まで）。
- 箱の中は「見出し1行＋補足1行」までにし、補足は `color: "ink"` で落とす。
- 図と箇条書きを併用する場合は `body` と `figure` の両方を指定（自動で2カラム）。

**`image` を使ってよい場合**: 写真・スクリーンショット・ロゴ画像など、図形で描けないものだけ。
図解をSVG/PNGで貼るのは禁止（build.py がSVGをエラーにする）。

**構造化ルール:**
- Markdown: `#`→title(表紙), `##`→各本文スライドの `title`, `###`→`body`の太字見出し, 段落/リスト→`body`。
  ただし**見出しをそのまま `title` にしない**。体言止めの見出しは、そのページの主張を表す言い切りの文に書き換える。
- 章立てが明確な資料は、各章の頭に `type:"section"` の章扉を入れると目次が章単位で自動生成される。
- 締めの要点ページは `type:"summary"` を使う。
- 1スライドの本文が多すぎる（目安: 箇条書き8行 or 本文10行超）なら複数スライドに分割する。
- `toc` は省略可（本文2枚以上で自動的に目次を付ける）。明示的に `"toc": false` で無効化。
- **目次の列挙対象**: 章扉(`section`)が1枚でもあれば章扉のタイトルを、無ければ本文/サマリーのタイトルを列挙する（ページ番号は自動計算）。
- `date` の既定は「住友商事株式会社 ｜ <今日>」。会社名・日付が不明なら部署名等で補い、勝手な固有名詞は入れない。

### Step 2: build.py で生成
spec.json を**成果物と同じフォルダに `spec.json` として保存し**（**UTF-8**。BOM有無どちらも可）、スキル同梱の build.py を実行する。
**一時ファイルにしない・作業後に消さない。** spec.json は資料のソースにあたり、修正依頼が来たときはこれを直して再ビルドする。

```bash
python "<SKILL_DIR>/assets/build.py" spec.json output.pptx
```

- `<SKILL_DIR>` はこのSKILL.mdのあるディレクトリ。`--template` 省略時は `assets/template.pptx` を使う。
- **依存:** `python-pptx` と `Pillow`。未導入なら先に `pip install python-pptx pillow` を実行する。
- Windowsで python が `py`/フルパスの場合はそれを使う。
- 図解の描画に追加ツールは不要（`figure` はオートシェイプとして直接生成される）。
- **使わなかったプレースホルダは自動削除される。** `section`/`lead` を省略したページ、図だけで本文が無いページ、
  `subtitle`/`date` を省略した表紙などで、空枠に「本文/図表/グラフなど」というプロンプト文字が残らない
  （ページ番号・日付・フッター枠は機能枠なので残す）。

### Step 3: QA（必須）
生成後に必ず確認する:
- スライド枚数 = 表紙 + (目次) + 各 slides(本文/章扉/サマリー) + エンド になっているか。
- **図が画像になっていないか**（必須）。1枚も画像が無いこと（写真を貼った場合はその枚数だけ）:
  ```bash
  python -c "from pptx import Presentation; p=Presentation('out.pptx'); print('pictures=', sum(1 for s in p.slides for sh in s.shapes if sh.shape_type is not None and 'PICTURE' in str(sh.shape_type)))"
  ```
- テキスト抽出で流し込み漏れ・文字化けがないか。
- **全ページを画像化して自分で目視し、直してから納品する**（必須）。
  はみ出し・重なり・不自然な余白・読みにくさを見つけたら、`figure` の箱を大きくする／文言を短くする／
  ページを分けるなどして直し、**再ビルドしてもう一度PNGで確認する**。
  文字が箱からはみ出すのは16pt下限があるとよく起きるので、必ず目で見る。
  直し切らないまま「できました」と報告しない。PowerPoint COM が使えるなら:
  ```powershell
  $pp=New-Object -ComObject PowerPoint.Application
  $pres=$pp.Presentations.Open("$PWD\out.pptx",$true,$false,$false)
  $pres.Export("$PWD\render","PNG",1600,900); $pres.Close(); $pp.Quit()
  ```
  出力された PNG を実際に読んで確認する。PowerPoint COM が無い環境ではその旨を利用者に伝え、
  「目視確認が未実施」であることを明示して渡す（黙って省略しない）。

### Step 4: 納品
output.pptx をユーザーに提示する（成果物として送る）。あわせて次を伝える:
- **`spec.json` を残してあること**と、その置き場所。修正依頼はこれを直して再ビルドすれば1分で反映できる。
- PNG目視で直した箇所があればその要点。目視確認をしていない場合はその事実。

## 注意・トラブルシューティング
- **本文が長い**: 1スライドに詰め込みすぎない。`slides` を分割して複数ページにする。
- **目次のページ番号**: build.py が表示ページ番号（0始まり）で自動計算する。手で書かない。
- **図が小さい/余白が出る**: `viewBox` のアスペクト比が配置枠と大きく違うと余白になる。全幅は約2.35:1、2カラム右は約1.1:1に合わせる。
- **図の文字がはみ出す/重なる**: 図内も16pt下限なので、想定より文字が大きくなっている。箱を大きくする・文言を短くする・要素を減らす。詰め込みすぎのサインなので、図を2枚に分けるのも有効。
- **「SVGの画像貼り付けは禁止されています」エラー**: 図解を `image` で貼ろうとしている。`figure` に書き直す。
  写真・スクショは `image` のままでよい（PNG/JPGはエラーにならない）。
- **色を変えたい等の例外要望**: テンプレの schemeClr を尊重しつつ、必要時のみ run に `solidFill` を足す。むやみにブランド色を上書きしない。
- **修復ダイアログが出る**: build.py は雛形スライドをリレーションごと削除済み。手でXMLを足した場合は pptx スキルの validate/clean を通す。
